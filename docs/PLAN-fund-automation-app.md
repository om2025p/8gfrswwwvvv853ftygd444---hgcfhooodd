ساخت یک اپ اندرویدی که با **یک لمس**، خودش وارد سامانهٔ ایزی‌تریدر مفید شود، دارایی دو صندوق («آتیه مفید» و «سینرژی») را استخراج کند، درصد تغییر را حساب کند، و نتیجه را طوری ذخیره کند که در **وب‌اپ‌های ثبت درصد ۴ و ۵** و در **دیدبان درصدها** دیده شود.

## ۲. 🏛️ معماری اصلی: Local-First

- ❌ بدون VPS
- ❌ بدون سرور اختصاصی
- ❌ بدون وابستگی اجرایی به Devin / OpenHands
- ❌ بدون GitHub Actions برای اجرای روزانه
- ❌ بدون MantleDB / Cloud Sync
- ✅ ذخیره در حافظهٔ داخلی گوشی
- ✅ اتصال اینترنت فقط برای ارتباط با کارگزاری + گیت‌هاب

### 🔑 نکتهٔ کلیدی: GitHub Actions ≠ GitHub API
- **GitHub Actions** = ربات روی سرور گیت‌هاب → **لازم نیست، و کاربر غیرفعالش کرده**
- **GitHub API** = آدرس ساده‌ای که اپ مستقیم با آن فایل را در گیت‌هاب می‌گذارد → **همین کافی است**

## ۳. 🔄 جریان کامل کار (Pipeline)

```
۱. کاربر یک دکمه می‌زند: ▶️ اجرای اتوماسیون
        ↓
۲. اپ بررسی می‌کند اینترنت وصل است
        ↓
۳. اپ WebView را باز می‌کند → login.emofid.com/Login
        ↓
۴. رمز از Android Keystore خوانده و خودکار پر می‌شود
        ↓
۵. تیک «این دستگاه را به خاطر بسپار» خودکار زده می‌شود
        ↓
۶. بررسی کوکی نشست:
   ├─ معتبر است → از OTP رد شو
   └─ منقضی است → متوقف شو، از کاربر کد OTP بخواه (تعاملی)
        ↓
۷. انتظار ~۸ ثانیه برای بارگذاری کامل اعداد (Hydration Buffer)
        ↓
۸. استخراج دارایی «آتیه مفید (۴)» با ۳ لایه:
   لایهٔ ۱: شنود پاسخ‌های API شبکه
   لایهٔ ۲: اسکن متن بدنهٔ صفحه
   لایهٔ ۳: پیمایش DOM
   (لایهٔ ۴: هوش مصنوعی Gemini در صورت شکست سه لایه)
        ↓
۹. استخراج دارایی «سینرژی (۵)» با همان ۳ لایه (مستقل)
        ↓
۱۰. محاسبهٔ درصد:  ((جدید − پایه) ÷ پایه) × ۱۰۰  → دو رقم اعشار
        ↓
۱۱. ذخیره در حافظهٔ اپ (localStorage داخلی WebView)
   کلیدهای آتیه: mofid_atie_percents / mofid_atie_history / mofid_atie_baseNumber
                  pension_baseNumber / pension_history
   کلیدهای سینرژی: energy_fund_synergy / sinergy_baseNumber / sinergy_history
        ↓
۱۲. به‌روزرسانی مقدار پایه (فقط پس از ذخیرهٔ موفق تاریخچه)
        ↓
۱۳. ساخت فایل‌های بکاپ: gold4_backup.json و gold5_backup.json
        ↓
۱۴. آپلود بکاپ‌ها به گیت‌هاب با GitHub API (خودکار، بدون Actions)
        ↓
۱۵. ساخت گزارش فارسی
        ↓
۱۶. کاربر کروم را باز می‌کند → gold4 / gold5 / دیدبان
   → صفحه خودش بکاپ را از گیت‌هاب می‌خواند → عدد جدید نمایش داده می‌شود
```

## ۴. 🧮 فرمول محاسبهٔ درصد (دقیقاً از کد فعلی)

```
diff    = newNum − baseNum
percent = (diff ÷ baseNum) × 100     →  toFixed(2)
```

### منطق «قله» (Peak) — باید حفظ شود
| شرط | نوع | رنگ |
|---|---|---|
| `newNum > قله` | سود خالص واقعی (عبور از قله) | 🟢 سبز |
| `base < newNum ≤ قله` | جبران ضرر / اصلاح قیمت | 🟠 نارنجی |
| `newNum < base` | کاهش ارزش صندوق | 🔴 قرمز |
| `newNum == base` | بدون تغییر | ⚪ خنثی |

- مقدار پایه صفر → **خطا** (نه محاسبه)
- درصد با **دو رقم اعشار**

## ۶. 🌐 استخراج داده از ایزی‌تریدر

### مسیر
```
login.emofid.com/Login  →  m.easytrader.ir/portfolio-fill
```

### روش (فقط WebView — کروم ممکن نیست)
کروم اجازه نمی‌دهد اپ دیگری داخل صفحه‌اش دست ببرد. پس اتوماسیون **اجباراً** داخل WebView خودِ اپ انجام می‌شود.

### ۴ لایهٔ استخراج
1. **شنود API:** پاسخ‌های JSON که کلمهٔ «سینرژی»/«آتیه» دارند، پیمایش و مقدار کل دارایی استخراج می‌شود.
2. **اسکن متن:** جست‌وجوی نام صندوق در متن صفحه و برداشتن بزرگ‌ترین عدد ≥ ۶ رقم نزدیکش.
3. **پیمایش DOM:** بالا رفتن از والدها تا رسیدن به ظرفی که نام صندوق و عدد را دارد.
4. **هوش مصنوعی (Gemini):** عکس صفحه → «عدد کجاست؟» (تور نجات در صورت تغییر ظاهر فرم)

### واحد
**ریال** (مقدار واقعی دارایی)

### بافر زمانی
~۸ ثانیه تأخیر قبل از خواندن اعداد (چون اعداد چند ثانیه بعد تزریق می‌شوند)
